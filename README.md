## Цель работы

Изучить механизм дерева объектов Qt, принцип владения объектами через родителя, автоматическое удаление дочерних объектов при уничтожении родителя, а также разобраться в корректном и некорректном использовании `setParent()` в приложениях Qt Widgets.

## Постановка задачи

Создать приложение Qt Widgets, содержащее не менее пяти виджетов. Реализовать отслеживание создания и уничтожения объектов через `qDebug()`, автоматическое удаление дочерних виджетов при удалении родителя, смену родителя с помощью `setParent()`, отсоединение объекта через `setParent(nullptr)`, а также безопасное отложенное удаление с помощью `deleteLater()`. Для хранения указателей на объекты, которые могут быть уничтожены, использовать `QPointer`.

## Теоретическое обоснование

### Дерево объектов QObject

Объекты, наследующие `QObject`, могут иметь одного родителя и несколько дочерних объектов. Такая связь образует дерево. Родитель владеет дочерними объектами: при уничтожении родителя Qt автоматически удаляет его детей.

### Родители виджетов

Для `QWidget` родитель задаёт не только владение объектом, но и визуальное размещение. Дочерний виджет отображается внутри родительского. При смене родителя с помощью `setParent()` меняется владелец и визуальная иерархия. После переноса между компоновками виджет нужно удалить из старой компоновки и добавить в новую.

### setParent(nullptr)

Вызов `setParent(nullptr)` отсоединяет виджет от прежнего родителя. После этого прежний родитель больше не удаляет его автоматически. Ответственность за удаление такого объекта нужно взять на себя.

### deleteLater() и QPointer

`deleteLater()` планирует удаление объекта на ближайший подходящий момент цикла событий Qt. Это удобно при работе с сигналами и слотами. `QPointer` — безопасный наблюдающий указатель на QObject: он автоматически становится пустым, когда объект уничтожается.

## Описание реализации

В программе созданы отслеживаемые классы `LogLabel`, `LogButton`, `LogLineEdit` и `LogPanel`. Их конструкторы и деструкторы выводят сообщения в Application Output.

Главное окно содержит несколько дочерних виджетов и панель-владельца. Кнопка перемещения меняет родителя одного виджета между панелью и главным окном. Перед переносом виджет удаляется из старой компоновки, после смены родителя добавляется в новую.

Кнопка удаления вызывает `deleteLater()` для панели. Если перемещаемый виджет в этот момент остаётся ребёнком панели, он удаляется вместе с ней. Если он предварительно перенесён в главное окно, он остаётся существовать.

Отдельная демонстрация создаёт временную панель с двумя дочерними метками. Одна метка остаётся дочерней, другая отсоединяется через `setParent(nullptr)`. Затем панель и отсоединённая метка удаляются через `deleteLater()`.

## Разбор ошибок и способы их предотвращения

1. **Висячий указатель после удаления родителя.** Если хранить обычный указатель на дочерний объект, после удаления родителя он может указывать на уже уничтоженный объект. Для наблюдения за временем жизни QObject используется `QPointer`.
2. **Виджет исчезает после смены родителя.** При вызове `setParent()` виджет может перестать отображаться в прежней компоновке. Решение — удалить его из старого layout, сменить родителя, добавить в новый layout и вызвать `show()`.
3. **Утечка памяти после setParent(nullptr).** Отсоединённый объект больше не удаляется прежним родителем. Поэтому после демонстрации отсоединения программа отдельно вызывает для него `deleteLater()`.
